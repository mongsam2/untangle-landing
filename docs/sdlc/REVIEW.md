## 2. 실제 AI 서버 연동

로컬에서 `untangle-ai`(`127.0.0.1:8000`)와 랜딩 프로덕션 서버(`localhost:3000`)를
연결해 대표 대화를 끝까지 실행했다. `GET /health`는 `{"status":"ok"}`를 반환했다.

확인한 흐름은 다음과 같다.

1. **맥락 질문** — 첫 사용자 메시지에 AI가 "논문은 지금 어느 단계까지 진행된 상태인가요?"로 되물었다.
2. **제안 허락** — 상황을 답하자 "이 내용으로 지금 할 일을 정리해서 제안해드려도 될까요?"로 허락을 구했다.
3. **큰 할 일 생성** — 허락 후 `tasks` 응답으로 큰 할 일 2개를 만들고, 채팅에 요약 카드(`오늘 할 일 2개` + 제목 2개 + `오늘에서 보기`)와 `오늘` 탭의 읽지 않음 점을 함께 표시했다. 자동 탭 전환은 일어나지 않았다.
4. **선택 부모 분해** — "논문 초안 마무리하기가 제일 막막해요"에 그 부모만 서브태스크 5개로 나눴고, 고르지 않은 "밀린 빨래 처리하기"는 그대로 유지됐다.
5. **직접 편집 후 후속 대화** — 오늘 화면에서 큰 할 일 제목을 "밀린 빨래 처리하기" → "빨래 한 바구니 돌리기"로 고친 뒤 대화를 이어가자, 다음 요청 본문의 `tasks`에 수정한 제목이 그대로 실렸고 AI가 그 항목을 분해했다.

요청 본문을 가로채 확인한 결과 최상위 키는 `messages`와 `tasks`뿐이고, `provider`와
`completedIds`는 들어가지 않았다. 할 일 객체의 키도 `id`, `title`, `description`,
`subtasks`만 있었다.

### 원문 비노출

- AI 서버 로그에는 요청마다 `request_id`, `provider`, `model`, `duration_ms`만 남았고
  대화·할 일 문자열은 0건이었다.
- 랜딩 프로덕션 서버 로그에는 요청 로그 자체가 없었다.
- 브라우저 콘솔에도 출력이 없었다.

## 3. 오늘 화면과 직접 편집 검증

실제 브라우저(Chrome)에서 확인했다.

- **키보드 재정렬** — 드래그 핸들에 초점 → `Space`로 집기 → `ArrowDown` → `Space`로 놓기가
  동작했다. 라이브 리전이 "laundry pile, 1번째 위치입니다." → "…2번째 위치입니다." →
  "…항목을 2번째 위치에 놓았습니다."로 한국어 안내를 순서대로 읽었고, 놓은 뒤 초점이
  핸들에 유지됐다. `Escape`는 "…순서 변경을 취소했습니다."와 함께 원래 순서를 되돌렸다.
- **그룹 경계** — 완료 그룹 첫 항목에서 `ArrowUp`을 눌러도 미완료 그룹으로 넘어가지 않았고,
  서브태스크도 다른 부모로 이동하지 않았다.
- **포인터 재정렬** — 마우스 드래그로 집기와 놓기가 활성화되는 것까지 확인했다. 자동화가
  중간 이동 없이 좌표를 건너뛰어 위치가 바뀌지는 않았으므로, 실제 손 조작은 사용자 확인이
  필요하다(아래 남은 이슈).
- **메뉴식 이동** — 더보기 메뉴의 `아래로 이동`으로 순서가 바뀌었고, 초점이 같은 항목의
  더보기 버튼에 남았으며 라이브 리전이 새 위치를 알렸다.
- **메뉴 닫기** — `Escape`로 닫히며 초점이 트리거로 돌아왔고, 바깥 클릭으로도 닫혔다.
  다른 카드의 메뉴를 열면 앞서 연 메뉴가 먼저 닫혀 동시에 열리지 않았다.
- **완료 전환** — 부모를 체크하면 서브태스크 5개가 함께 완료되고 항목이 완료 그룹 끝으로
  이동했으며, 이동 뒤에도 초점이 그 체크박스에 남았다. `Space` 키로도 동작했다.
- **추가·수정·삭제 취소** — 추가 후 `할 일 추가` 버튼, 수정 후 더보기 트리거로 초점이
  돌아왔다. 삭제 확인 화면은 초점이 `취소`에 가고, 그 버튼이
  `aria-describedby="task-editor-heading task-editor-delete-result"`로 제목과 결과 설명을
  함께 읽어준다. `Escape`로 닫으면 트리거로 초점이 복귀하고 항목은 삭제되지 않았다.
- **요청 중 잠금** — AI 응답을 기다리는 동안 `할 일 추가`, 드래그 핸들 5개, 더보기 5개,
  `서브태스크 추가` 3개가 모두 비활성이고 체크박스 5개는 활성이었다. 응답 후 잠금이 풀렸다.
- **영속성** — 새로고침 뒤 대화, 목록 순서, 완료 상태가 그대로 복원됐다.

## 4. 화면과 키보드 검증

- **반응형** — 320px, 390px, 480px에서 `/demo`의 대화·오늘·편집 모달을 확인했다. 세 폭 모두
  가로 스크롤이 없었고(`scrollWidth === clientWidth`), 하단 탭과 입력이 가려지지 않았다.
  넓은 화면에서는 기존 최대 480px 열이 유지된다.
- **랜딩과 소감·처리방침** — 320px에서 랜딩, 390px에서 `/register`, 480px에서 `/privacy`를
  확인했다. 랜딩의 섹션 순서와 문구는 그대로다.
- **탭 이동** — `role="tab"`, `aria-selected`, roving tabindex가 붙어 있고 `ArrowRight`로
  탭과 초점이 함께 이동했다.
- **소감 링크** — 오늘 화면 하단 링크가 `/register?from=demo`로 연결되고, 해당 화면에서
  평점 선택과 낮은 점수 이유 블록이 정상 동작했다.

## 5. 이번 검증에서 고친 문제

- `useSortable`의 `transition: null`은 라이브러리가 무시하는 값이라 제거했다.
- `DragDropProvider`에 인라인 함수로 `plugins`/`sensors`를 넘기면 렌더마다 새 배열이
  만들어져 플러그인이 반복 재생성되므로, 모듈 수준 상수로 바꿨다.
- 더보기 메뉴를 `details`에서 상태 기반 버튼으로 바꿔 `Escape`·바깥 클릭 닫기와 동시 열림
  방지를 추가했다.
- 메뉴식 이동 결과를 알리는 한국어 라이브 리전을 추가했다.
- 편집기를 닫을 때 초점이 사라지지 않도록 폴백을 부모 체크박스 → 추가 버튼 → 패널 순으로 넓혔다.
- 드래그 핸들의 영문 `aria-roledescription` 기본값을 한국어로 대체했다.
- 화면의 7개·100자·500자 상한을 `CHAT_LIMITS` 하나로 모았고, 입력 길이 제한을 공백 제거
  기준으로 맞췄다.
- 네이티브 검증이 한국어 오류 안내를 가로채지 않도록 `noValidate`를 넣었다.
- 사용되지 않던 `markTodayRead`·`replaceTasks` 액션과 중복 검증 헬퍼를 제거했다.
- 파일 설명 블록 주석을 규약대로 모든 import 아래로 옮겼다.

## 6. 남은 이슈

차단 이슈는 없다. 다음 두 가지는 사용자 판단이 필요하다.

1. **규약 문서의 예시 경로** — `AGENTS.md`(144·160·169·194·266·272행)와
   `docs/conventions/git.md`(18·21·156행)가 이번에 삭제한 `lib/llm.ts`,
   `app/api/split/route.ts`, `components/split/*`를 코드·브랜치·커밋 예시로 쓴다. 코드에는
   영향이 없지만 존재하지 않는 경로를 가리킨다. 승인된 plan의 단계 6 작업 목록에 규약 문서
   수정이 없어 임의로 고치지 않았다.
2. **포인터 드래그의 실제 재정렬** — 자동화로는 집기와 놓기까지만 확인했다. 마우스와 터치로
   위치가 실제로 바뀌는지는 손으로 한 번 확인하는 편이 좋다.

참고로 개발 서버는 `localhost:3000`으로 접속해야 한다. `127.0.0.1`로 열면 Next.js가 개발
리소스 요청을 교차 출처로 차단해 화면이 하이드레이션되지 않는다.
