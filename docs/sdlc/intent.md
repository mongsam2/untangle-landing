# Intent: 대화형 Untangle 데모와 분리된 오늘 할 일

## 문제

현재 `/demo`는 브레인덤프, 후보 선택, 선택한 일 분해와 오늘 할 일 확인이 서로 다른
단계로 고정되어 있다. 랜딩 페이지의 설명과는 맞지만, 새 `untangle-ai`가 제공하는 짧고
자연스러운 대화, 제안 허락, 큰 할 일 생성과 선택 항목 분해 경험을 보여주지 못한다.
또한 랜딩 서버가 GPT와 Claude를 직접 호출해 AI 서버와 별도의 행동 계약과 공급자
설정을 유지하고 있다.

기존 데모의 마지막 단계에만 오늘 할 일이 있어, 사용자가 대화를 계속하면서 목록을
확인하고 실행하거나 직접 수정하기 어렵다. 완료 상태와 직접 편집은 새 AI 서버의 할 일
스키마에 포함되지 않으므로, 데모가 그 책임을 명확하게 나누어야 한다.

## 의도

`/demo`를 하나의 연속된 대화 경험으로 바꾸고, 대화에서 만들어진 최신 목록을 별도의
`오늘` 화면에서 실행하고 관리할 수 있게 한다. AI와의 대화는 `untangle-ai`의 승인된
행동 계약을 그대로 사용하며, 랜딩의 Next.js 서버는 브라우저 요청을 AI 서버에 전달하는
얇은 경계만 담당한다.

사용자는 AI의 질문에 자연어로 답하고, AI가 할 일을 만들거나 고쳐도 자동으로 화면이
전환되지 않는다. 채팅에서 변경 요약을 확인한 뒤 하단의 `오늘` 탭이나 명시적인 버튼으로
목록을 연다. `오늘` 화면에서는 AI 대화와 별개로 할 일을 직접 편집하고 완료할 수 있다.

## 영향을 받는 사용자와 시스템

- 가입 없이 실제 Untangle 대화 경험을 시험하는 랜딩 방문자
- 데모 UI, 브라우저 저장소와 서버 프록시를 제공하는 `untangle-landing`
- 무상태 `POST /v1/chat` 계약을 제공하는 `untangle-ai`
- 데모 뒤 선택적으로 소감을 받는 기존 `/register` 화면

랜딩 페이지 본문의 설명과 CTA 문구는 바꾸지 않는다. `untangle-ai`의 공개 API와 대화
행동도 이 작업에서 변경하지 않는다.

## 원하는 사용자 경험

### 연속된 대화

- 첫 방문에는 Untangle이 먼저 짧고 답하기 쉬운 질문을 보여준다.
- 이후에는 단계 화면 없이 하나의 채팅에서 대화를 이어간다.
- 공급자 선택 UI를 두지 않고 AI 서버의 기본 공급자를 사용한다.
- AI가 목록을 만들거나 수정하면 채팅에는 메시지와 간단한 변경 요약, `오늘에서 보기`
  버튼을 보여준다.
- 목록이 생겨도 자동으로 `오늘` 화면으로 이동하지 않는다.
- AI 응답을 기다리거나 오류가 발생해도 사용자가 작성한 내용과 기존 대화가 사라지지
  않아야 한다.

### 대화와 분리된 오늘 할 일

- 화면 하단에 항상 `대화`와 `오늘` 두 탭을 둔다.
- 새 목록을 아직 보지 않았다면 `오늘` 탭에 작은 표시를 보여준다.
- 할 일이 없을 때는 빈 상태 안내와 `대화에서 정리하기` 버튼을 보여준다.
- 큰 할 일에는 제목, 설명과 서브태스크를 표시한다.
- 사용자는 큰 할 일과 서브태스크를 직접 추가, 수정, 삭제하고 순서를 바꿀 수 있다.
- 큰 할 일의 직접 추가와 수정에서는 제목과 설명을 다루고, 서브태스크는 제목만 다룬다.
- 완료하지 않은 항목을 먼저 보여주고 완료한 항목은 체크된 상태로 아래에 남긴다.
- 서브태스크를 모두 완료하면 부모도 완료한다. 부모 완료를 전환하면 모든 서브태스크도
  함께 전환한다.
- AI 서버의 상한에 맞춰 큰 할 일과 부모별 서브태스크를 각각 최대 7개로 제한한다.

### 저장과 재방문

- 대화, 최신 할 일 목록과 완료 상태를 브라우저 저장소에 보관한다.
- 같은 브라우저로 다시 방문하면 선택 화면 없이 저장된 상태를 즉시 복원한다.
- 날짜가 바뀌어도 저장된 대화, 목록과 완료 상태를 유지한다.
- 데모 안에는 전체 초기화 기능을 제공하지 않는다. 사용자는 브라우저의 사이트 데이터
  삭제 기능으로 로컬 데이터를 지울 수 있다.
- 기존 단계형 데모의 저장 데이터는 새 구조로 변환하지 않고 무시한다.
- 완료 상태는 브라우저 전용 정보다. AI 서버에는 대화와 할 일 내용만 전달한다.

### 직접 편집

- 큰 할 일과 서브태스크의 수정·삭제는 각 항목의 더보기 메뉴에서 시작한다.
- 드래그 핸들로 같은 목록 안에서 순서를 바꾼다.
- 목록과 부모 카드의 추가 버튼으로 큰 할 일과 서브태스크를 만든다.
- 사용자가 직접 바꾼 최신 전체 목록은 다음 AI 요청의 현재 목록으로 전달한다.
- AI가 기존 항목을 수정해 반환하면 ID가 같은 항목의 로컬 완료 상태를 유지한다.

### 체험 마무리

- 기존 `/register` 체험 소감 화면은 유지한다.
- 완료 직후 팝업이나 슬라이드업으로 소감을 요구하지 않는다.
- `오늘` 화면 하단에 `체험 소감 남기기` 링크를 둔다.

## 시스템과 개인정보 원칙

- 브라우저는 AI 서버를 직접 호출하지 않고 같은 사이트의 Next.js 서버를 호출한다.
- Next.js 서버는 환경 변수로 지정한 AI 서버의 `/v1/chat`에 요청을 전달하며 대화나 할
  일을 저장하지 않는다.
- 대화 원문과 할 일 내용은 제품 분석 이벤트나 애플리케이션 로그에 남기지 않는다.
- PostHog 분석, 세션 재생, 관련 SDK·환경 변수·문서와 개인정보 안내를 저장소 전체에서
  제거한다.
- 개인정보 처리방침은 새 대화 전송, 브라우저 저장과 실제 삭제 방법에 맞게 최소한으로
  갱신한다.

## 포함 범위

- `/demo`의 연속 채팅과 `오늘` 탭 UI
- `untangle-ai` 요청·응답 계약에 맞는 클라이언트 상태와 Next.js 서버 프록시
- 브라우저 저장, 자동 복원, 완료 상태와 직접 목록 편집
- 기존 소감 화면으로 가는 방해 없는 링크
- 기존 단계형 데모, 직접 LLM 호출 API와 OpenAI·Anthropic SDK 제거
- PostHog 전체 제거와 그에 따른 개인정보 처리방침·설정 문서 정리
- 자동 검사, 로컬 AI 서버 연동 확인과 실제 화면 검증

## 제외 범위

- 랜딩 페이지 본문의 설명, CTA 문구와 섹션 구성 변경
- `untangle-ai`의 공개 API, 프롬프트 또는 공급자 설정 변경
- 사용자 계정, 서버 저장소와 기기 간 동기화
- 완료 상태를 AI에 전달하거나 AI가 완료 여부를 판단하는 기능
- 날짜별 목록, 자동 이월 또는 과거 기록 화면
- 데모 안의 전체 초기화 기능
- 배포와 배포 환경 구성

## 성공한 모습

- 방문자는 단계 화면 없이 대화를 시작하고 AI가 상황을 이해하는 흐름을 경험한다.
- AI가 만든 할 일과 선택한 항목의 서브태스크가 별도 `오늘` 화면에 정확히 반영된다.
- 사용자가 직접 바꾼 목록은 다음 대화에 반영되고, AI가 목록을 바꿔도 기존 완료 상태가
  불필요하게 사라지지 않는다.
- 재방문과 날짜 변경 뒤에도 새 데모의 대화, 목록과 완료 상태가 복원된다.
- 브라우저는 AI 서버의 주소와 공급자 키를 알 필요가 없고, Next.js 서버는 원문을
  저장하거나 로그에 남기지 않는다.
- PostHog 코드와 설정이 남지 않고 개인정보 처리방침이 실제 동작과 일치한다.
- 랜딩 본문은 변경되지 않으며 자동 검사와 로컬 연동·화면 검증이 통과한다.

## 설계 단계로 넘길 질문

- 브라우저 상태 모델과 기존 ID별 완료 상태를 보존하는 조정 방식
- 메시지 64개와 본문 256 KiB 상한 안에서 장기 대화를 유지하는 방식
- 프록시의 입력 검증, 타임아웃과 AI 서버 오류 표시 계약
- 직접 추가하는 항목의 UUID 발급 위치와 동시 요청 중 편집 충돌 방지
- 접근 가능한 드래그 재정렬과 모바일 키보드·스크롤 처리
- 기존 저장 키와 PostHog 브라우저 데이터의 정리 범위

이 질문들은 제품 의도를 바꾸지 않는 구현 설계 사항이며 `spec.md`에서 결정한다.

## 승인 요청

제품 책임자는 다음을 확인한다.

- 랜딩 본문은 유지하고 `/demo`만 새 AI 서버 기반 경험으로 교체하는 범위가 맞는가
- 연속 채팅과 분리된 `오늘` 화면의 책임이 의도와 맞는가
- 직접 편집·완료·브라우저 저장 규칙과 초기화 기능 제외가 맞는가
- PostHog 전체 제거와 개인정보 안내 갱신이 맞는가
- 로컬 검증에서 종료하고 배포를 제외하는 완료 범위가 맞는가

승인 후 `상태`, `승인일`, `승인자`를 갱신하고 `spec.md`를 작성한다.
